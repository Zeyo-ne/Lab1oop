# Лабораторная 1. Moon Mining Inc.

Калькулятор времени и прибыли по контракту на добычу руды.

Флот летает к астероидному поясу, добывает руду часовыми циклами и возвращается
на станцию для переработки. Поддерживаются контракты на срок и на объём,
корабли Venture, Prospect и Epithal, общий и раздельные трюмы.

## Сборка и тесты

Нужен .NET SDK 10.0.100 или новее. Из папки репозитория:

```sh
dotnet restore
dotnet build --no-restore
dotnet test --no-build
```

Решение `Itmo.ObjectOrientedProgramming.slnx` можно открыть в Rider или другой IDE.
Это библиотека с тестами, отдельной консольной программы нет.
Настройки сборки, версии пакетов и GitHub Actions взяты из шаблона.

## Стиль кода

Код оформлен по [Google C# Style Guide](https://google.github.io/styleguide/csharpguide.html):
отступы по 2 пробела, строки до 100 символов, открывающая скобка на той же строке,
`System` первым в списке `using`, свойства перед конструкторами, вложенные типы в начале класса.
Учебная структура папок и пространства имён сохранены из шаблона.

Правила для редактора заданы в `.editorconfig`, для форматирования — в `.clang-format`.
Отключены только проверки StyleCop, противоречащие выбранному стилю.
`Directory.Build.targets` не даёт пакету из шаблона перезаписать эти правила при сборке.
Для проверки оформления всех исходников и тестов (нужен `clang-format`):

```sh
git ls-files '*.cs' | xargs clang-format --dry-run --Werror
```

## Структура

- `Models` — руда, минералы, пояс, флот, станция и прайс-лист.
- `Ships` — характеристики кораблей и их добыча за цикл.
- `Storage` — трюмы и стратегии размещения руды.
- `Contracts` — ограничения контракта и условия начала рейса и цикла.
- `Simulation` — выполнение рейса и переработка руды.
- `Results` — выполненный или отклонённый контракт.
- `Calculator` — проверка контракта, выполнение рейсов и расчёт денег.

Характеристики объектов неизменяемы. Загрузка трюмов и склад станции относятся
к отдельному расчёту, поэтому повторный расчёт не использует прежние остатки.
Время, объёмы и деньги хранятся в `decimal`, целые единицы руды и минералов — в `long`.

## Расширение

Новую руду или минерал можно создать через `Ore` и `Mineral`.
Новый корабль наследует `Ship`, новая стратегия реализует `IStorageStrategy`,
новый контракт наследует `Contract`. Проверки конкретных типов в калькуляторе нет.
Примеры расширений находятся в `ExtensionTests`.

## Границы из условия

Для старта рейса используется строгое `<`, а для проверки срока и начала цикла — `<=`.
Поэтому при расстоянии 4 а.е., одном Venture и сроке ровно 3 часа контракт
принимается, но не выполняет ни одного рейса. Это буквальное следование условию;
граница отдельно проверяется тестом.

Объём руды округляется вниз до целых единиц после каждого рейса.
Целые остатки на складе переносятся между рейсами, дробная часть единицы теряется.
Для Pyroxeres используется объём единицы `0.3` из таблицы задания.
Деньги дополнительно не округляются. Отрицательная прибыль не означает отклонение.

## Тесты

Пять обязательных сценариев находятся в `ContractScenarioTests`.
Остальные тесты проверяют добычу и границы времени, стратегии хранения,
переработку, налог, точность расчётов, неизменяемость и некорректные аргументы.
